# Post editor (`/editor`)

**Back:** [web overview](../../overview.md) · **Related:** [architecture](architecture.md), [auth](auth.md), [app-header](app-header.md)

## Purpose

Authenticated screen for composing and editing a post: title field and rich body using **Lexical** (`lexical`, `@lexical/react`, `@lexical/rich-text`, `@lexical/list`, `@lexical/link`, `@lexical/table`, `@lexical/code`, `@lexical/markdown`). One editor component (`LexicalPostEditor`) serves every surface; post-only features are switched on by props. Legacy parity: [legacy-parity.md](../../editor/legacy-parity.md).

## Route and access

| Item | Detail |
|------|--------|
| Path | `/editor` — [`apps/web/src/app/(app)/editor/page.tsx`](../../../../apps/web/src/app/(app)/editor/page.tsx) |
| Auth | Server Component calls `createCookieAuthContextProvider().getUser()`; if `null`, `redirect('/')`. Unauthenticated users cannot view the editor. |
| Entry | Logged-in **write** icon in [`LoggedInHeaderActions`](../../../../apps/web/src/modules/app-header/presentation/components/logged-in-header-actions.tsx) → `/editor`. |

## Implementation

| Area | Detail |
|------|--------|
| Module | [`apps/web/src/modules/editor/`](../../../../apps/web/src/modules/editor/) — `EditorScreen`, `LexicalPostEditor`, insert overlay, format toolbar, **`EditorAdvancedSettingsPanel`**, **`EditorAttachedObjectsPanel`**, **`EditorPublishDock`**, **`EditorPostPreviewModal`**; application `lexical-state-to-markdown`, `post-editor-advanced-settings`, `use-editor-post-publish`; domain `format-actions`, `SpoilerNode`, `post-editor-linked-object`, `post-editor-advanced-settings`; drafts in infrastructure. |
| Layout | Main column uses **`max-w-container-content`** (not `container-narrow`). |
| UI | Design tokens (see [theme.md](../../theme.md)); body placeholder uses i18n `story_placeholder`; page title from `editor` in `generateMetadata`. |
| Insert menu | **+** on the left border tracks the caret. Dialog grid: **Photo** (upload panel), **Video** (legacy-style inline field at the caret line — (+) turns into ✕, "Paste video link and press Enter" + **Enter**; a YouTube / Instagram / TikTok / Facebook / X / LinkedIn URL becomes a **`VideoNode`** that shows the same embedded player as the post; pasting a lone video link does the same; markdown is the bare URL on its own line, which the renderer embeds; old drafts / posts with a linked video paragraph import as players), **Object** (inline search at caret: **+** → **✕**, placeholder `objects_auto_complete_placeholder`, dropdown via `/api/search`), **Line** (`LineNode` — a plain `<hr>` element node with the same `horizontalrule` JSON type as Lexical's decorator node, so old drafts load; → `---`; goes after the whole current block — code / table / list are never split; on an empty line it goes above it), **Code** (current block → `CodeNode`, fenced on publish), **Table** (2×2 with header row, `@lexical/table` → GFM; equal fixed-width columns, long text wraps and grows the row, rows striped white / grey with the header row styled like any other (legacy look) — same in the published post via `.blog-post-body table`; while the caret is in a table the block toolbar offers **+ Row**, **+ Column** — both append at the end — and **Remove table** (trash icon)), **Emoji** (`emoji-picker-react`, native glyphs, lazy-loaded). Google Maps places are found through [`#` object search](../../editor/hash-object-search.md) — there is no separate Nearby item. Object pick inserts a **Lexical link** (visible name, `href` = `{origin}/object/{id}`) and appends to `jsonMetadata.objects` when id is new (removing the link in the editor does **not** remove metadata). Line / Code / Table are post-editor only. i18n: `editor_insert_*`. |
| `#` object search | Typing `#` opens our object search; with `POST_EDITOR_GOOGLE_PLACES_ENABLED=true` also Google Maps places near the user (off by default), and a new place is created as an object signed by the author. Spec: [hash-object-search.md](../../editor/hash-object-search.md). |
| Caret around blocks | Block kinds (`application/block-gaps.ts`): **flow** (paragraph, heading, quote, list), **container** (table, code), **media** (image, video, line). The document always ends with a flow line — re-added after edits (root transform) and after a draft loads (`setEditorState` skips transforms, so an update listener re-checks); empty paragraphs are dropped on publish. Arrows (`EditorBlockGapsPlugin`): from a text line onto a media block → the block is selected; from a selected media block → the neighbour (caret or selection), or a new line at the document edge; out of a table (edge row) / code block (edge line) with no flow line on that side → a new line. Enter or typing on a selected media block opens a line below it and types there. |
| Block toolbar | `EditorBlockToolbarPlugin`, floating above the active block (below it when there is no room under the site header): **↑ Line** / **↓ Line** for every table, code and selected media block — the touch way out, phones have no arrow keys; tables also **+ Row**, **+ Column**, remove (trash); image / video / line also remove (trash). Re-clamped to the viewport with a `ResizeObserver`. Verified at 390 and 320 px. |
| Block keys | Image, video and line blocks: Backspace / Delete next to one first **selects** it (accent ring, text caret hidden), the next press removes it and puts the caret where the user was (start of the next block, else end of the previous). Handled synchronously inside the Lexical key command (`EditorImageKeyboardPlugin`). The (+) follows Lexical's selection: a selected block, else the DOM caret line (padding-aware for empty blocks). |
| Paste | A selection copied from a post (page or modal) or any web page keeps its blocks and formatting — headings, lists, tables, code, bold / italic / struck text, links, image and video blocks, lines: [rich-paste.md](../../editor/rich-paste.md). Pasted links to `…/object/<id>` (HTML or text, any host) attach those objects (`EditorPasteObjectLinksPlugin`, by-ids lookup, max 20 per paste); the links stay in the body. |
| Edit published post | Post page **Edit** → `/editor?author=<me>&permlink=<p>`. A saved edit draft (draft with `permlink`) wins; otherwise the published post loads (`GET /posts/:author/:permlink` → `body`, `jsonMetadata`, `parentPermlink`). Markdown body → Lexical via `@lexical/markdown` + post transformers (image, bare image URL, `---`, GFM table); raw HTML stays text. Legacy `wobj.wobjects` become `objects`. Publish re-broadcasts **`comment` only** with the same permlink and parent; published `json_metadata` keys are kept, editor-owned keys win. Reward / beneficiaries / self-upvote are locked (`editor_edit_payout_locked`). After confirm → post page. |
| Format toolbar | Floating bar (`EditorFormatToolbar`) on **non-compact** editors when the user selects text (hidden on collapsed/zero-width selection). Primary: Bold, Italic, Link, More (…). More menu driven by `MORE_ACTIONS` in `domain/format-actions.ts` (H1–H3, Quote, inline code, Spoiler, Mention stub). Positioned above selection via `createPortal` + `position: fixed`; `onMouseDown` `preventDefault` preserves selection. Link opens inline URL field with editor-state snapshot restore on cancel. i18n: `editor_format_*`. |
| Images | **Non-compact** editor only: paste image file or a lone **image-like URL** (`EditorPasteImagePlugin` — pathname image extension or content-gateway `/ipfs-gateway/content/image/{cid}`; other `http(s)` URLs and URLs inside copied text insert as text; images inside pasted HTML keep their URL, see [rich-paste.md](../../editor/rich-paste.md)); drag-drop on editor shell (`EditorImageDropOverlay`), Insert → Photo (`EditorInsertPhotoPanel` + shared `IpfsImageDropZone`). Upload via `uploadImageToIpfs` / `uploadImageFromUrl`; `ImageNode` stores `cid` + `src`. Draft `body` is Lexical JSON. Publish converts body via `lexical-state-to-markdown.ts`. |
| Advanced settings | Collapsible **`EditorAdvancedSettingsPanel`** (closed by default) **above** linked objects: **Reward** (`fifty_fifty` → `percent_hbd: 10000`, `hive_power` → `0`, `declined` → `max_accepted_payout: 0.000 HBD` per [Hive `comment_options`](https://developers.hive.io/apidefinitions/broadcast-ops.html)). **Beneficiaries** (user search + weight sliders; author share = remainder). Default beneficiary from server env `POST_EDITOR_DEFAULT_BENEFICIARY_ACCOUNT` / `POST_EDITOR_DEFAULT_BENEFICIARY_PERCENT` ([`post-editor-defaults.ts`](../../../../apps/web/src/config/post-editor-defaults.ts)). **Like this post** (self-upvote, off by default) adds `vote {voter: author, weight: 10000}` to the publish transaction. **Hashtags** → `json_metadata.tags` (default chip `waivio`, removable). Reward mode and self-upvote live in draft metadata as `_editorRewardMode` / `_editorSelfUpvote` (stripped on publish). |
| Bottom dock | Fixed bar (same chrome as object-create `PendingOpsDock`): status line from `resolveEditorPublishDockStatus` — **ready to publish** or a warning (`editor_post_not_ready_*`, `linked_objects_remaining`). **Preview** / **Publish** require non-empty title and body (Lexical text or image), valid linked-object percents, valid beneficiaries, and legal checkbox. Permlink from title via `titleToPostSlug` (Cyrillic transliteration, max slug 128, Hive `[a-z0-9-]`, max 255). **Publish post** broadcasts Hive **`comment`** + **`comment_options`** (+ self **`vote`** when enabled; edit mode: `comment` only), `awaitTrxConfirmation`, deletes draft, navigates to `/@username`. Legal checkbox: `legal_notice_create_post`. |
| Linked objects | Below advanced settings: search (`/api/search` via `fetchObjectSearchResults`). On load, all stored `object_id`s are hydrated in one `POST /api/search/objects-by-ids` → query-api `loadByObjectIds` + projection (no FTS / meta_group dedup). **Create new object** opens **`EditorCreateObjectModal`** (name, locale, searchable type, optional like) — flush autosave first; on-chain quick create via `buildEditorQuickCreateOps` (`object_create` + `name` + supposed updates), then `attachReturnedObject` without leaving the editor. The full **`/object-create`** page remains at that URL; optional `?return=` + `attachObject` still works when that page is used. The account menu does not link to it. Cards: toggle (detach) and independent percent sliders (equal split only on add/remove). State in draft **`jsonMetadata.objects`**. When a linked object has **`object_type: hashtag`** (linked-objects search, Insert → Object, or `attachObject` return), the editor also adds the normalized tag to **Advanced settings** → `json_metadata.tags` if it is not already present. See [post-json-metadata-objects.md](../../../spec/data-model/post-json-metadata-objects.md), [`editor-create-object-modal.tsx`](../../../../apps/web/src/modules/editor/presentation/components/editor-create-object-modal.tsx), [`build-editor-quick-create-ops.ts`](../../../../apps/web/src/modules/object-create/application/build-editor-quick-create-ops.ts). Autosave: [drafts/page.md](../drafts/page.md). |

## Limits

- Campaign / review / giveaway flows of the legacy editor are not ported (no campaigns in the new stack). Parity table: [legacy-parity.md](../../editor/legacy-parity.md).
- Editing imports markdown only: raw HTML in old posts (`<center>`, `<img>`) stays as text.
- Reward **50/50** uses `percent_hbd: 10000` (Waivio-compatible), not Hive docs’ `5000` basis-point interpretation for the same UI label.

## Verification

Open `/editor` logged out → redirect to `/`. Logged in → editor UI; header write icon navigates to `/editor`.
